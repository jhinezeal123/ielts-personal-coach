# Content channel — contract (v1)

Goal: new lessons reach installed apps **without an app release**. App releases (tags `vX.Y.Z`) are only for features.
Content is published by pushing to `main`; installed apps pull it daily.

## Layout in the repo

```
content/
  manifest.json          # generated by scripts/build-content-manifest.mjs — never hand-edit
  packs/<pack-id>.js     # one pack per file (hand-written or generated)
```

## Pack file format (classic script, no modules)

```js
IELTS.registerPack({
  id: "bbc-6min-01",              // unique, kebab-case, == file name
  version: 1,                     // bump when the pack's content changes
  minAppVersion: "1.1.0",         // app skips the pack if IELTS_VERSION is lower
  title: "BBC 6 Minute English — tập 1–10",
  source: "BBC Learning English (bbc.co.uk/learningenglish) — dùng cá nhân, không thương mại",
  assets: [                       // audio files the sync script downloads to app/content-packs/audio/<file>
    { file: "bbc-6min/260101.mp3", url: "https://...mp3" }
  ],
  listeningTests: [ /* SPEC §6.1, sections may set audio: "asset:<file>" */ ],
  listeningClips: [ /* see below */ ],
  readingTests:   [ /* SPEC §6.2 */ ],
  dictation:      [ /* SPEC §6.4 */ ],
  vocabWords:     [ /* SPEC §6.5 */ ]
});
```
All collection keys are optional. IDs must be globally unique (prefix with something not used by built-in data,
e.g. `BBC-…`, `BC-L1`). IDs are progress keys — never rename a published ID.

### Audio references
Any `audio` field may be `"asset:<file>"`. The app resolves it to `content-packs/audio/<file>` (relative to
`app/index.html`); if that local file fails to load it falls back to the asset's remote `url`. If both fail, a listening
section falls back to TTS of its `script`.

### `listeningClips` (new: real-audio practice, not full IELTS tests)
```js
{
  id: "BBC-6M-260101", title: "…", source: "BBC Learning English — 6 Minute English", sourceUrl: "https://…",
  level: "medium" | "hard", topic: "<SPEC §6.6 topic>", duration: "6:12",
  audio: "asset:bbc-6min/260101.mp3",
  context: "Two presenters discuss …",                         // English
  transcript: [ { speaker: "Neil", text: "…", q: [1] } ],      // shown only after submit
  groups: [ /* SPEC §6.3 groups, numbered from 1 */ ]          // 6–10 questions per clip, Vietnamese `explain`
}
```

## manifest.json (generated)
```json
{
  "schema": 1,
  "contentVersion": 3,                  // incremented by the builder whenever any pack hash changes
  "generatedAt": "2026-10-17T10:00:00Z",
  "packs": [
    { "id": "bbc-6min-01", "file": "packs/bbc-6min-01.js", "version": 1, "minAppVersion": "1.1.0",
      "title": "…", "sha256": "<hex of pack file>",
      "assets": [ { "file": "bbc-6min/260101.mp3", "url": "https://…" } ] }
  ]
}
```

## Installed side (gitignored — keeps the git tree clean so app updates still fast-forward)
```
app/content-packs/
  index.js            # window.IELTS_CONTENT_INDEX = { contentVersion, syncedAt, packs: [{id, file, version, minAppVersion}] }
  packs/<id>.js
  audio/<file>
```
- `scripts/sync-content.ps1` downloads `https://raw.githubusercontent.com/jhinezeal123/ielts-personal-coach/main/content/manifest.json`,
  downloads changed packs (verify sha256), downloads missing assets, removes packs no longer listed, then rewrites `index.js` last
  (atomic: a failed sync leaves the previous index working). Run by `auto-update.ps1` after its release check, so the existing
  scheduled task (07:00 + logon) and `cap-nhat-ngay.cmd` cover it.
- The app loads `content-packs/index.js` (optional, like `update-status.js`), injects each pack script whose `minAppVersion`
  ≤ `IELTS_VERSION`, and boots only after all packs have loaded or errored.

## Publishing new lessons
1. Add/edit `content/packs/<id>.js` (bump its `version` when editing).
2. `node scripts/build-content-manifest.mjs` (validates + regenerates manifest, bumps contentVersion).
3. `node scripts/check-content.mjs` then commit and push to `main`. **No tag, no release.**
